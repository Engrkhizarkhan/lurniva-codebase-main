# Lurniva

A pnpm + Turborepo monorepo for Lurniva.

## Structure

```
apps/
  landing/    NextJs marketing/landing site (static)
  web/        TanStack Start product frontend (React)
  api/        TanStack Start backend/API (file-based /api/* routes)
  model/      TanStack Start AI service (book-to-skill style content structuring,
              study plans, grounded Q&A, assessments) — see apps/model/README.md
packages/
  types/       Shared TypeScript types
  validation/  Shared Zod schemas (consumed by web forms and the API)
  ui/          Shared React components
  config/      Shared runtime/env config helpers
  db/          Prisma client + schema (Supabase Postgres)
tooling/
  eslint-config/      Shared flat ESLint configs (base, react, node)
  typescript-config/  Shared tsconfig bases
```

Each app is independently deployable: `landing`, `web`, and `api` each build and start on their own, and only depend on the shared `packages/*`.

## Prerequisites

- Node.js >= 22.12.0
- pnpm >= 9 (`corepack enable` will pick up the pinned version)
- A Supabase Postgres project (or any Postgres instance) for `packages/db`

## Setup

```bash
pnpm install

# Copy env files and fill in real values
cp packages/db/.env.example packages/db/.env
cp apps/api/.env.example apps/api/.env
cp apps/web/.env.example apps/web/.env
cp apps/landing/.env.example apps/landing/.env
cp apps/model/.env.example apps/model/.env   # + OPENAI_API_KEY / MODEL_NAME
```

The model service (`apps/model`) and the web app's real AI provider both read
`OPENAI_API_KEY` + `MODEL_NAME`. Leaving them unset keeps the web app on its
offline mock; setting them activates real, content-grounded model responses.

## Development

```bash
pnpm dev            # runs dev servers for every app in parallel via Turborepo
pnpm --filter @lurniva/web dev    # run a single app
```

Default ports: landing `4321`, web `3000`, api `3001`.

## Common tasks

```bash
pnpm build        # turbo run build (respects dependency graph)
pnpm lint          # eslint across all packages
pnpm typecheck     # tsc --noEmit across all packages
pnpm format        # prettier --write
pnpm db:studio     # open Prisma Studio
```

## Notes

- `src/routeTree.gen.ts` in `apps/web` and `apps/api` is generated by the TanStack Router Vite plugin on `dev`/`build`. A checked-in copy exists only so a fresh clone can typecheck before the first `pnpm dev`/`pnpm build` — don't hand-edit it.
- `packages/db` uses Prisma's `prisma-client` generator with a driver adapter (`@prisma/adapter-pg`) targeting Supabase: `DATABASE_URL` (pooled, port 6543) is used at runtime, `DIRECT_URL` (port 5432) is used by the CLI for migrations, configured via `packages/db/prisma.config.ts`.
- `apps/api` sends permissive CORS headers to `CORS_ORIGIN` (defaults to the `web` dev server) so `apps/web` can call it directly during development.
